# 🌡️ おでかけ日和度モデル ｜ モデルカード

`model/comfort_model.pkl` の説明書です。
天気4項目から、その日の**「おでかけ日和度」を 0〜100点で予測する**モデルです。

カテゴリ予測モデル（[doc/README.md](README.md)）が「**どこへ**行くか」を決めるのに対して、
こちらは「**どのくらい良い日か**」を数字で表します。
分類ではなく**回帰**（数値を当てる問題）なので、成績の見方も変わります。

- 学習スクリプト：[train_comfort.py](../train_comfort.py)
- 機械が読める成績表：[model/comfort_card.json](../model/comfort_card.json)
- 学習データ：[doc/dataset.md](dataset.md)（カテゴリ予測モデルと同じもの）

## 1. ひとことで言うと

| 項目 | 内容 |
| --- | --- |
| 種類 | 教師あり学習 / **回帰**（0〜100点を当てる） |
| アルゴリズム | 勾配ブースティング木（`HistGradientBoostingRegressor`） |
| 入力 | 気温・降水確率・風速・湿度（カテゴリ予測モデルと同じ4つ） |

| 学習データ | 103,024 日（47都市・6年） |

```python
score = model.predict(pd.DataFrame(
    [[22, 10, 2, 50]],

```

## 2. 点数のつけ方

気象データに「その日は何点か」という正解はないので、
**気象の指標をもとにした減点方式**で正解を作っています。

```text
体感温度 = 気温 - 1.5 × √風速
不快指数 = 0.81×気温 + 0.01×湿度×(0.99×気温 - 14.3) + 46.3

素点 = 100
      - 1.8 × max(0, 22 - 体感温度)     ← 寒いほど減点
      - 2.4 × max(0, 気温 - 26)         ← 暑いほど大きく減点
      - 0.45 × 降水確率                 ← 雨がいちばん重い
      - 1.6 × max(0, 風速 - 3)          ← 風が強いと減点
      - 1.2 × max(0, 不快指数 - 75)     ← 蒸し暑いと減点
（0〜100点におさめる）
```

### 「人によるちがい」を足す

同じ天気でも、良い日だと感じる度合いは人によってちがいます。
そこで素点に**標準偏差6点のばらつき**（正規分布のノイズ）を足したものを正解にしています。

これには大事な意味があります。ばらつきが無いと、モデルは上の式を丸暗記するだけになり、
誤差ゼロ・R²＝1.000 という**見せかけの満点**が出てしまいます。
ばらつきを入れることで、**どんなモデルでも越えられない壁**ができます。

### 理論上の下限（＝満点）

素点をそのまま答えても、ばらつきのぶんだけ誤差が残ります。それが下限です。

| 指標 | 下限（これ以上は縮められない） |
| --- | --- |
| MAE | **4.62 点** |
| RMSE | 5.85 点 |
| R² | 0.914 |

### できあがった点数の分布

| | |
| --- | --- |
| 平均 | 70.6 点 |
| 標準偏差 | 20.0 点 |

## 3. モデルの選び方

候補5つを、学習用データの**5分割交差検証**で比べ、
**MAE がいちばん小さいもの**を選びました。

| 順位 | モデル | MAE | RMSE | R² | ばらつき |
| --- | --- | --- | --- | --- | --- |
| 🥇 | **勾配ブースティング** | **4.688** | **5.880** | **0.914** | ±0.018 |
| 2 | ランダムフォレスト | 4.812 | 6.053 | 0.908 | ±0.016 |
| 3 | 決定木（深さ8） | 5.141 | 6.443 | 0.896 | ±0.024 |
| 4 | 線形回帰 | 7.489 | 9.484 | 0.775 | ±0.025 |
| – | ベースライン（いつも平均点 70.6 を答える） | 15.929 | 20.010 | -0.000 | ±0.069 |

読み取れること。

- ベースラインの MAE 15.9 → 4.7 なので、**予測が大きく効いています**
- **線形回帰は MAE 7.49 で頭打ち**です。
  点数の式には `max(0, ...)` という折れ曲がりが入っていて、
  まっすぐな直線では表せません。ここが**木のモデルとの差**として出ています
- 上位3つはどれも木の仲間で、勾配ブースティングがわずかに勝ちました
- データが5倍に増えたことで、**候補どうしの MAE のばらつきが大きく縮みました**
  （勾配ブースティングで ±0.068 → ±0.018）。順位の信頼度が上がったということです

### 選ばれたモデルの設定

```python
HistGradientBoostingRegressor(
    max_iter=400,
    learning_rate=0.06,
    max_leaf_nodes=31,
    l2_regularization=1.0,
    random_state=42,
)
```

## 4. 成績

学習に使っていない**評価用データ 20,605 件**での結果です（信頼区間は95%）。

| 指標 | 結果 | 下限（満点） |
| --- | --- | --- |
| MAE（平均どれくらいズレたか） | **4.67点** [4.62〜4.72] | 4.62点 |
| RMSE | **5.87点** | 5.85点 |
| 決定係数 R² | **0.913** | 0.914 |
| 誤差5点以内だった割合 | 61.2% | – |
| 誤差10点以内だった割合 | **91.2%** | – |
| いちばん大きく外した誤差 | 25.9点 | – |

**MAE 4.67点に対して下限が 4.62点**。差はわずか 0.05点で、
**この問題で縮められる誤差は、ほぼ縮め切っています**。
残りは「人によって感じ方がちがう」ぶんなので、モデルをどれだけ工夫しても消えません。

### 点数の帯ごとのズレ（かたより）

MAE が小さくても、点数の帯によって**答えのかたより方**があります。
bias が＋なら実際より高めに、－なら低めに出しています。

| 点数の帯 | 件数 | MAE | かたより |
| --- | --- | --- | --- |
| 0〜39点 | 1,689 | 5.27点 | **+2.44**（低い点数を高めに出す） |
| 40〜59点 | 3,675 | 4.87点 | +1.71 |
| 60〜79点 | 7,775 | 4.65点 | +0.65 |
| 80〜100点 | 7,466 | 4.45点 | **-2.09**（高い点数を低めに出す） |

これは**平均への回帰**と呼ばれる、回帰モデルによくあるくせです。
極端に低い・高い点数ほど、モデルは自信を持てず平均寄りに答える傾向があります。
「90点」と出た日は実際には少し低めのことが多く、「30点」と出た日は少し高めのことが多い、
と読んでください。

### 都市ごとの成績（両端）

| 都市 | MAE | ひとこと |
| --- | --- | --- |
| 横浜 | **4.98**（最も苦手） | |

| 天気 | 予測 | ひとこと |
| --- | --- | --- |

## 5. 使いどころ

- 予測結果の画面に「**今日のおでかけ日和度：92点**」と出す
- 何日かぶんを並べて「**この中でいちばん良いのは土曜日**」と示す
- 点数が低い日は、プランの屋外スポットを減らす

カテゴリ（outdoor / indoor / relax）は3種類しかないので、
「同じ outdoor でも、今日は特別に良い日」という差がつけられません。
点数を併せて出すと、その差が伝わります。

---

## 6. 限界・注意点

1. **点数は人がつけたものではありません。** 気象指標にもとづく減点方式で作った疑似データです。
   実際のアンケートを取れば、季節感やイベントなど別の要素が効くはずです。
2. **減点の重みは決め打ち**です（雨 0.45／暑さ 2.4 など）。
   「雨でも平気」「暑いのが苦手」といった好みは反映されません。
3. **カテゴリ予測モデルとは別々に学習しています。**
   点数が高いのに `indoor` が出る、といった食いちがいが起こることがあります。
4. **極端な点数ほど、平均寄りに出やすい**傾向があります（第4章「点数の帯ごとのズレ」参照）。
5. **学習データの範囲の外**（気温 39.1℃ 超・湿度 15% 未満）は苦手です。
6. 0点や100点にはりつく日があるため、**両端では誤差が読みにくく**なります。
