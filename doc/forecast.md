# 🌤️ 翌日の天気予測モデル ｜ モデルカード

`model/forecast_model.pkl` の説明書です。
**きのう・きょうの天気から、あしたの天気を当てる**モデルで、
天気予報APIを使わずに「あしたのお出かけプラン」を作るために用意しました。

- 学習スクリプト：[train_forecast.py](../train_forecast.py)
- 機械が読める成績表：[model/forecast_card.json](../model/forecast_card.json)
- 学習データ：[doc/dataset.md](dataset.md)（カテゴリ予測モデルと同じもの）

---

## 1. ひとことで言うと

| 項目 | 内容 |
| --- | --- |
| 種類 | 教師あり学習 / **多出力回帰**（数値を4つ同時に当てる）＋分位点回帰（予測区間） |
| アルゴリズム | `MultiOutputRegressor(HistGradientBoostingRegressor)`（点予測）＋<br>`HistGradientBoostingRegressor(loss="quantile")` × 3分位点 × 4項目（区間） |
| 入力 | きょう・1日前・2日前の天気＋3日平均＋前日差＋季節＋都市（**23列**） |
| 出力 | **あした**の 気温・降水確率・風速・湿度（4つの数値）＋その80%予測区間 |
| 学習データ | 102,883 行（47都市・2019〜2024年） |
| 検証方法 | **ウォークフォワード検証**（2021〜2024年、年ごとに「過去で学習→次の年を予測」を繰り返す） |
| 成績 | 気温 MAE **1.72℃**（持続予報 1.85℃ より 7.3% 改善） |

分類モデル（[doc/README.md](README.md)）と組み合わせると、こう使えます。

```text
きょうまでの天気 → 【このモデル】 → あしたの天気 → 【カテゴリ予測モデル】 → あしたのおすすめ
```

実際にこの経路をつないだものが `outing_ml/forecasting.py` の `ForecastService` で、
Web アプリの `/forecast` 画面・`/api/forecast` から使えます（[doc/webapp.md](webapp.md)）。

## 2. 入力と出力

### 入力（23列）

4項目それぞれについて、次の5つを作っています（4×5＝20列）。

| 列 | 意味 |
| --- | --- |
| `〇〇_today` | きょうの値 |
| `〇〇_lag1` | 1日前の値 |
| `〇〇_lag2` | 2日前の値 |
| `〇〇_mean3` | 直近3日の平均（その時期らしさが出る） |
| `〇〇_diff` | きょう − きのう（上がっているのか下がっているのか） |

これに次の3列を足します。

| 列 | 意味 |
| --- | --- |
| `season_sin` / `season_cos` | 季節。1年でひと回りするので、日付を角度に直して sin と cos にする |
| `city` | 都市名（47種類。0/1 の列に展開して使う） |

> 💡 **なぜ sin と cos の2つ使うのか**
> 12月31日と1月1日は「隣どうし」なのに、日付の番号（365と1）で見ると
> いちばん離れた値になってしまいます。角度に直して sin と cos の2つで表すと、
> 年をまたいでも自然につながります。

### 出力

あしたの `temperature` / `rain_probability` / `wind_speed` / `humidity` の4つ（点予測）と、
それぞれの**80%予測区間**（10%点〜90%点）。予測値はアプリのスライダーの範囲
（気温 -10〜40℃ など）におさめてから返します。

### 使い方

学習済みモデルは `outing_ml.registry.ModelBundle` の形式で保存されています。
`estimator` の中に、点予測のモデルと分位点のモデルが辞書で入っています。

```python
from outing_ml.registry import load_bundle
from outing_ml.config import CONFIG

bundle = load_bundle(CONFIG.paths.forecast_model)
point_model = bundle.estimator["point"]
quantile_models = bundle.estimator["quantiles"]   # {列名: {分位点: モデル}}

# 特徴量は outing_ml.features.build_prediction_frame() で作る
tomorrow = point_model.predict(features[bundle.feature_names])   # → [気温, 降水確率, 風速, 湿度]
```

直接この形式を扱わなくても、`ForecastService.load().predict_tomorrow(city)` を呼べば、
都市名だけで「直近の実測取得 → 特徴量作成 → 予測 → カテゴリ予測モデルへ」まで一気に行います。

## 3. 学習と評価の分け方（ここが一番大事）

時系列データを**ランダムに分けてはいけません**。
未来の日が学習用に、過去の日が評価用に入ってしまい、
「未来を見てから過去を当てる」というズルになるからです（データ漏洩）。

さらに、**1回だけ時間で区切って評価するのも十分ではありません**。
たまたまその年が当てやすかっただけかもしれないためです。
そこで、本番と同じ順番で年をまたいで何度も検証する
**ウォークフォワード検証**を使っています。

```text
2020年までで学習 → 2021年を予測
2021年までで学習 → 2022年を予測
2022年までで学習 → 2023年を予測
2023年までで学習 → 2024年を予測
```

各都市の最初の2日（前々日が無い）と最後の1日（あしたが無い）は使えないので、
103,024 行のうち 102,883 行を使っています。

## 4. 成績（2021〜2024年、年ごとの平均）

### 平均絶対誤差（MAE。小さいほど良い）

| 予測するもの | **このモデル** | 年ごとのばらつき | 持続予報<br>（あした＝きょう） | 平年値<br>（都市×月の平均） | 持続予報からの改善 |
| --- | --- | --- | --- | --- | --- |
| 気温（℃） | **1.72** | ±0.03 | 1.85 | 2.51 | **7.3%** |
| 降水確率（%） | **24.53** | ±0.74 | 26.40 | 25.52 | **7.1%** |
| 風速（m/s） | **1.21** | ±0.02 | 1.46 | 1.26 | **17.2%** |
| 湿度（%） | **8.62** | ±0.06 | 10.24 | 9.74 | **15.8%** |

年ごとのばらつきが小さいのは良い兆候です。「たまたま当てやすい年があっただけ」
ではなく、**どの年でも同じくらいの精度**が出ています。

### 未来のデータ（2025〜2026年、学習中に一度も見ていない）での確認

| 予測するもの | このモデル | 持続予報 | 平年値 |
| --- | --- | --- | --- |
| 気温（℃） | **1.74** | 1.92 | 2.75 |
| 降水確率（%） | **23.88** | 26.05 | 25.04 |
| 風速（m/s） | **1.15** | 1.31 | 1.27 |
| 湿度（%） | **9.40** | 10.94 | 11.59 |

ウォークフォワード検証（1.72℃）と未来データ（1.74℃）でほぼ同じ数字が出ており、
評価の見積もりが本番でも大きく崩れないことを確認できました。

### くらべた相手（ベースライン）

- **持続予報**…「あしたも、きょうと同じ天気」と答えるだけ。
  天気は続きやすいので、実はかなり当たります。**これに勝てないと意味がありません。**
- **平年値**…「その都市の、その月の平均」を答えるだけ。季節のことしか知らない予報です。

### 読み取れること

- **4項目すべてで、2つのベースラインに勝っています。**
- **風速・湿度の改善が大きい**（15〜17%）一方、**気温・降水確率の改善は控えめ**（7%前後）です。
  気温はもともと持続予報が強い項目で、これ以上のばすには
  気圧・上空の風など、このデータに入っていない情報が必要です。
- **降水確率の MAE は 24 ポイント**あり、決して小さくありません。
  雨は「降るか降らないか」の差が大きく、過去の地上観測だけで当てるのは難しい問題です。

## 5. 予測区間（想定80%）の実力

点で1つだけ答えると、外れたときにどれくらい外れるか分かりません。
そこで「10%点」「90%点」も別に学習し、その間を**80%予測区間**として出しています。

| 項目 | 想定カバレッジ | 実際に入った割合 | 区間の幅（平均） |
| --- | --- | --- | --- |
| 気温 | 80% | **73.0%** | 4.9℃ |
| 降水確率 | 80% | **89.5%** | 71.7pt |
| 風速 | 80% | **73.9%** | 3.3 m/s |
| 湿度 | 80% | **73.4%** | 27.0pt |

**想定80%に対して、気温・風速・湿度は実際には73〜74%しか入っておらず、区間が狭すぎます**
（自信過剰）。逆に降水確率は89.5%と広めに外れており、区間が広すぎます。
つまりこの分位点モデルは**較正が取れていません**。区間を「だいたいこのくらい」という
目安以上には使わないでください。この点は次のバージョンで改善したい課題です。

## 6. おすすめカテゴリまで通した成績

このモデルの本当の役目は「あしたのおすすめ」を出すことなので、
**予測した天気をカテゴリ予測モデルに入れて、実測の天気で出したおすすめと比べました。**

| あしたの天気の出し方 | 実測の天気と同じおすすめになった割合 |
| --- | --- |
| **このモデル** | **61.5%** |
| 持続予報（あした＝きょう） | 60.6% |
| 平年値（都市×月の平均） | 57.1% |

**「あした」の話になると、5日に2日はおすすめが変わってしまいます。**
天気の予測誤差、とくに降水確率のズレが、そのままカテゴリの取り違えになるためです。
持続予報との差はわずか0.9ポイントで、**このモデルを使う価値はそれほど大きくありません**。

このことから、実際にアプリで使うなら次のどちらかが正しい姿です。

1. **きょうの天気**（手入力または実況）でおすすめを出す ← Gradio版アプリの既定
2. あしたの予報を使うなら、**気象庁や天気予報APIの本物の予報値**を渡す

このモデルは「予報を作るのがどれだけ難しいか」を体験するための教材、
という位置づけで見てください。

## 7. 数日先までの週間予報（再帰予測）

`ForecastService.predict_week()` を使うと、1日先だけでなく**最大7日先**まで
予報を作れます（Web アプリの `/week` 画面・`/api/week`）。

学習・特徴量づくりは「1日先を当てる」形のままです。2日先以降は、
**前日ぶんの予測結果を実測の続きとして入力に足し、もう一度同じモデルで予測する**
という再帰的なやり方で作っています。

```text
実測（〜today） → 【モデル】 → day1（あした）の予測
実測＋day1の予測 → 【モデル】 → day2（あさって）の予測
実測＋day1＋day2の予測 → 【モデル】 → day3の予測
...
```

### これは検証していない使い方です

1日先の予測モデルとしての成績（第4〜6章）は、実際の観測データで確かめています。
しかし**この再帰予測じたいの精度は検証していません**。1日目の誤差が2日目の入力に乗り、
2日目の誤差が3日目に乗り……と、先に行くほど誤差が積み重なる構造になっています。

これを目に見える形にするため、予測区間の幅を日数の平方根に比例させて広げています
（`day_index ** 0.5` を掛けるだけの簡易な近似で、統計的な裏付けは取っていません）。
実際の値がこの区間に収まる割合（カバレッジ）が本当にそうなるかは確認していないので、
**「だいたいこのくらい誤差が広がっていく」という目安**として見てください。

3日目以降のカテゴリ予測（indoor/outdoor/relax）も、同じ理由で当てにしすぎないでください。

## 8. 限界・注意点

1. **本物の天気予報にはかないません。**
   気象庁の予報は、大気の動きを物理計算したスーパーコンピュータの結果を使っています。
   このモデルが見ているのは、地上の4項目の過去3日分だけです。
2. **急変に弱いです。** 台風・寒波・前線の通過など、
   「きのうまでの流れから外れる日」はうまく当てられません。
3. **1日先まで**しか予測できません。2日先を出したい場合は、
   予測結果をもう一度入力に使うことになり、誤差がふくらみます。
4. **学習した47都市（全都道府県庁所在地）でしか使えません。** 都市名が入力に入っているため、
   知らない都市を渡すと（0/1 の列がすべて0になり）精度が落ちます。
5. **予測区間は較正が取れていません**（第5章参照）。想定80%に対し実際は73〜90%とばらつきます。
6. **降水確率は本物の予報値ではありません**（[doc/dataset.md](dataset.md) 参照）。

## 9. 作り直す手順

```bash
python fetch_weather.py     # データが無いときだけ
python train_model.py       # 先にカテゴリ予測モデルを作っておく（第6章の評価に使う）
python train_forecast.py
```

| できあがるファイル | 中身 |
| --- | --- |
| `model/forecast_model.pkl` | 学習済みモデル（点予測＋分位点）と、入力列の名前 |
| `model/forecast_card.json` | ウォークフォワード検証・未来データ・予測区間の記録 |

配布する `.pkl` は、成績を確かめたあと**全期間（2019〜2024年）で学習し直した**ものです。
