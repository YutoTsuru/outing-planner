# 🌤️ 翌日の天気予測モデル ｜ モデルカード

`model/forecast_model.pkl` の説明書です。
**きのう・きょうの天気から、あしたの天気を当てる**モデルで、
天気予報APIを使わずに「あしたのお出かけプラン」を作るために用意しました。

- 学習スクリプト：[train_forecast.py](../train_forecast.py)
- 機械が読める成績表：[model/forecast_card.json](../model/forecast_card.json)
- 学習データ：[doc/dataset.md](dataset.md)（カテゴリ予測モデルと同じもの）

---

## 1. ひとことで言うと

| 項目 | 内容 |
| --- | --- |
| 種類 | 教師あり学習 / **多出力回帰**（数値を4つ同時に当てる） |
| アルゴリズム | `MultiOutputRegressor(HistGradientBoostingRegressor)` |
| 入力 | きょう・1日前・2日前の天気＋3日平均＋前日差＋季節＋都市（**23列**） |
| 出力 | **あした**の 気温・降水確率・風速・湿度（4つの数値） |
| 学習データ | 19,701 行（学習 16,416 ／ 評価 3,285） |
| 分け方 | **時間で分割**（学習：2019〜2023年 ／ 評価：2024年） |
| 成績 | 気温 MAE **1.66℃**（持続予報 1.81℃ より 8.3% 改善） |

分類モデル（[doc/README.md](README.md)）と組み合わせると、こう使えます。

```text
きょうまでの天気 → 【このモデル】 → あしたの天気 → 【カテゴリ予測モデル】 → あしたのおすすめ
```

## 2. 入力と出力

### 入力（23列）

4項目それぞれについて、次の5つを作っています（4×5＝20列）。

| 列 | 意味 |
| --- | --- |
| `〇〇_today` | きょうの値 |
| `〇〇_lag1` | 1日前の値 |
| `〇〇_lag2` | 2日前の値 |
| `〇〇_mean3` | 直近3日の平均（その時期らしさが出る） |
| `〇〇_diff` | きょう − きのう（上がっているのか下がっているのか） |

これに次の3列を足します。

| 列 | 意味 |
| --- | --- |
| `season_sin` / `season_cos` | 季節。1年でひと回りするので、日付を角度に直して sin と cos にする |
| `city` | 都市名（0/1 の列に展開して使う） |

> 💡 **なぜ sin と cos の2つ使うのか**
> 12月31日と1月1日は「隣どうし」なのに、日付の番号（365と1）で見ると
> いちばん離れた値になってしまいます。角度に直して sin と cos の2つで表すと、
> 年をまたいでも自然につながります。

### 出力

あしたの `temperature` / `rain_probability` / `wind_speed` / `humidity` の4つ。
予測値はアプリのスライダーの範囲（気温 -10〜40℃ など）におさめてから返します。

### 使い方

```python
import joblib, pandas as pd

bundle = joblib.load("model/forecast_model.pkl")
model, input_columns = bundle["model"], bundle["input_columns"]

# 特徴量は train_forecast.build_features() で作るのがかんたんです
tomorrow = model.predict(features[input_columns])   # → [気温, 降水確率, 風速, 湿度]
```

## 3. 学習と評価の分け方（ここが一番大事）

時系列データを**ランダムに分けてはいけません**。
未来の日が学習用に、過去の日が評価用に入ってしまい、
「未来を見てから過去を当てる」というズルになるからです（データ漏洩）。

そこで、**時間で区切って**分けています。

| | 期間 | 件数 |
| --- | --- | --- |
| 学習用 | 2019-01-01 〜 2023-12-31 | 16,416 |
| 評価用 | 2024-01-01 〜 2024-12-31 | 3,285 |

各都市の最初の2日（前々日が無い）と最後の1日（あしたが無い）は使えないので、
19,728 行のうち 19,701 行を使っています。

## 4. 成績（2024年のデータで評価）

### 平均絶対誤差（MAE。小さいほど良い）

| 予測するもの | **このモデル** | 持続予報<br>（あした＝きょう） | 平年値<br>（都市×月の平均） | 持続予報からの改善 |
| --- | --- | --- | --- | --- |
| 気温（℃） | **1.66** | 1.81 | 2.49 | **8.3%** |
| 降水確率（%） | **24.05** | 27.09 | 25.21 | **11.2%** |
| 風速（m/s） | **1.36** | 1.63 | 1.45 | **17.0%** |
| 湿度（%） | **7.88** | 9.34 | 9.33 | **15.6%** |

### 二乗平均平方根誤差（RMSE。大きく外した回数が効く）

| 予測するもの | このモデル | 持続予報 | 平年値 |
| --- | --- | --- | --- |
| 気温（℃） | **2.18** | 2.47 | 3.10 |
| 降水確率（%） | **29.85** | 39.86 | 31.11 |
| 風速（m/s） | **1.76** | 2.24 | 1.87 |
| 湿度（%） | **10.13** | 12.62 | 11.67 |

### くらべた相手（ベースライン）

- **持続予報**…「あしたも、きょうと同じ天気」と答えるだけ。
  天気は続きやすいので、実はかなり当たります。**これに勝てないと意味がありません。**
- **平年値**…「その都市の、その月の平均」を答えるだけ。季節のことしか知らない予報です。

### 読み取れること

- **4項目すべてで、2つのベースラインに勝っています。**
- とくに**降水確率は RMSE で 39.86 → 29.85 と大きく改善**しました。
  持続予報は「きのう大雨だから、あしたも大雨」と大外しすることがありますが、
  このモデルは季節や気圧のうつり変わり（気温・湿度の動き）から抑えぎみに答えます。
- 一方で**気温の改善は 8.3% にとどまります**。
  もともと持続予報が強い項目で、これ以上のばすには
  気圧・上空の風など、このデータに入っていない情報が必要です。
- **降水確率の MAE は 24 ポイント**あり、決して小さくありません。
  雨は「降るか降らないか」の差が大きく、過去の地上観測だけで当てるのは難しい問題です。

## 5. おすすめカテゴリまで通した成績

このモデルの本当の役目は「あしたのおすすめ」を出すことなので、
**予測した天気をカテゴリ予測モデルに入れて、実測の天気で出したおすすめと比べました。**

| あしたの天気の出し方 | 実測の天気と同じおすすめになった割合 |
| --- | --- |
| **このモデル** | **62.9%** |
| 持続予報（あした＝きょう） | 60.4% |
| 平年値（都市×月の平均） | 57.6% |

**「あした」の話になると、3日に1回はおすすめが変わってしまいます。**
天気の予測誤差、とくに降水確率のズレが、そのままカテゴリの取り違えになるためです。

このことから、実際にアプリで使うなら次のどちらかが正しい姿です。

1. **きょうの天気**（手入力または実況）でおすすめを出す ← 現在のアプリ
2. あしたの予報を使うなら、**気象庁や天気予報APIの本物の予報値**を渡す

このモデルは「予報を作るのがどれだけ難しいか」を体験するための教材、
という位置づけで見てください。

## 6. 限界・注意点

1. **本物の天気予報にはかないません。**
   気象庁の予報は、大気の動きを物理計算したスーパーコンピュータの結果を使っています。
   このモデルが見ているのは、地上の4項目の過去3日分だけです。
2. **急変に弱いです。** 台風・寒波・前線の通過など、
   「きのうまでの流れから外れる日」はうまく当てられません。
3. **1日先まで**しか予測できません。2日先を出したい場合は、
   予測結果をもう一度入力に使うことになり、誤差がふくらみます。
4. **学習した9都市でしか使えません。** 都市名が入力に入っているため、
   知らない都市を渡すと（0/1 の列がすべて0になり）精度が落ちます。
5. **降水確率は本物の予報値ではありません**（[doc/dataset.md](dataset.md) 参照）。
