# アクセシビリティ対応

Web アプリ（`webapp.py`）の画面が、キーボード操作とスクリーンリーダーで
使えるようにするために行った対応をまとめます。完璧な監査ではなく、
明らかな欠落（label の無い入力欄・role の無いエラー表示など）を
機械的なテストで守れる範囲にとどめています。

## やったこと

### キーボード操作

| 対応 | 内容 |
| --- | --- |
| スキップリンク | 各ページの先頭に「本文へ移動」というリンクを置いた。ふだんは画面外にあり、Tabキーで最初にフォーカスが当たったときだけ見える。ナビゲーションを毎回読み飛ばして本文へ直接ジャンプできる |
| フォーカスの見た目 | 入力欄・ボタン・リンクすべてに、キーボード操作時だけ（`:focus-visible`）はっきりした輪郭を出す。マウス操作では出ない |
| メインランドマーク | 各ページの本文を `<main id="main-content">` で囲み、スキップリンクの飛び先にした |

### スクリーンリーダー

| 対応 | 内容 |
| --- | --- |
| フォームの label | すべての `input` / `select` に `label for` を対応する `id` へ関連付けている（新規に追加した画面も含めて確認済み） |
| ナビゲーションの現在地 | `<nav aria-label="主要ナビゲーション">` に、いま開いているページへ `aria-current="page"` を付けている |
| 装飾的な絵文字 | カテゴリの絵文字（🌳🏛️☕など）は、隣に同じ意味のテキストが必ずあるため `aria-hidden="true"` で隠し、スクリーンリーダーが絵文字の読み上げと文字の読み上げを二重にしないようにした |
| 警告・注意書き | 範囲外の入力・データソースの案内など、通常の操作に添える注意書き（`.warn`）には `role="status"`（ゆるやかな読み上げ）を付けた。ページ全体がエラーになる404/500/503のエラー画面には `role="alert"` を付けている |
| 表の説明 | 表（都市の比較、学習の履歴、天気タイプの一覧など）に `<caption>` を追加した。見出し（`<h2>`）で視覚的には説明済みのため、`class="sr-only"`（画面には出さずスクリーンリーダーだけに読ませる）にしている |
| 表の見出しセル | すべての `<th>` に `scope="col"` を付け、列見出しであることを明示した |

### 色のコントラスト

ドリフト監視画面の判定（OK / 要観察 / 要対応）の文字色を、背景に対して
WCAG AA基準（通常の文字で4.5:1以上）を満たすように確認・調整した。

| 色 | 明るいテーマ | 暗いテーマ |
| --- | --- | --- |
| OK | 5.34:1 | 8.62:1 |
| 要観察 | 5.91:1（調整前は4.10:1で基準未達だった） | 9.75:1 |
| 要対応 | 6.22:1 | 7.17:1 |

### 動きを減らす設定

`prefers-reduced-motion: reduce` が指定されている環境では、アニメーションと
トランジションをすべて無効にする（すでに対応済みだったものを維持）。

## 対応していないこと

- 画面全体を実際のスクリーンリーダー（VoiceOver・NVDA等）で通しては確認していません。テストは「必要な属性が出力の中にあるか」を確かめるところまでです
- キーボードだけで全操作が完了するかの手動確認（Tabキーでの実機操作）はしていません
- コントラストの確認は主要な状態表示の色にとどめており、すべての組み合わせを網羅してはいません

## テスト

`tests/test_accessibility.py` で、生成されたHTMLに次を確認しています。

- スキップリンクとメインランドマークの存在
- ナビゲーションの `aria-label` と `aria-current`
- すべての入力欄に対応する `label for` があること
- 絵文字の `aria-hidden`
- 警告の `role="status"`、エラー画面の `role="alert"`
- 表の `caption` と `scope="col"`
